1. 工具用途 / Purpose

本工具將 Schedule、COOIS、ZRMM0028 與 MB52 合併，先以母料 F+G 共用池覆蓋母料需求，再把不足量展開成子料需求，最後依順序扣減子料 MB52 庫存。所有處理都在本機瀏覽器完成。

The tool combines Schedule, COOIS, ZRMM0028, and MB52. It first covers mother demand from the shared F+G pool, expands only the shortage to child demand, and then consumes child MB52 stock in order. All processing stays in the local browser.

真實業務檔案不得上傳到外部服務，也不得提交 Git。
Do not upload real business files to external services or commit them to Git.

3. 操作流程 / Operating steps

步驟一：匯入四份報表 / Step 1: Import four reports

  1. 分別選取 Schedule、COOIS、ZRMM0028、MB52。/ Select each of the four inputs.
  2. 確認四個槽位都顯示匯入成功。/ Confirm all four slots show a successful import.
  3. COOIS／0028 若是雙表頭，系統會採英文表頭列。/ For dual-header COOIS/0028 files, the English header row is used.
0028 在所有檢核前會排除母料或子料以 MB 開頭的整列。
Before any validation, 0028 rows whose mother or child starts with MB are removed.

步驟二：確認欄位與換算 / Step 2: Confirm mappings and conversions

  1. 檢查欄位是否對到正確英文表頭。/ Check each mapping against the correct English header.
  2. 檢查一般單位與 SHT 尺寸換算；220x110cm SHT → YD 必須是 2.187227。/ Check unit and SHT size conversions; 220x110cm SHT → YD must be 2.187227.
  3. 可用「匯入換算 JSON／匯出換算 JSON」與 Python 驗證器共用設定。/ Use conversion JSON import/export to share the same settings with the Python verifier.
缺少換算、係數不合法或同一關係有衝突時，整批停止。請修正資料或設定後重新執行，不會默默略過。
Missing, invalid, or conflicting conversions stop the entire run. Fix the source or configuration and rerun; rows are never silently skipped.

步驟三：執行、檢視與匯出 / Step 3: Run, review, and export

  1. 按「執行配發」。/ Click Run allocation.
  2. 先查看輸出列數、短缺列，再用 SO、日期或料號篩選。/ Review output and shortage counts, then filter by SO, date, or material.
  3. 核對 H `mother stock available before this row`、N `demand qty`、Q `provided qty` 與 R `remaining stock after this row`；G 與 H 不得相加。/ Reconcile H, N, Q, and R; do not add G and H.
  4. 匯出 CSV 或 XLSX；兩種格式皆為同一 19 欄順序。/ Export CSV or XLSX; both use the same 19-column order.
任何輸入、欄位對應或換算設定改變後，舊結果立即失效，匯出會停用；必須重新執行。
Any input, mapping, or conversion change immediately invalidates old results and disables export until rerun.

4. 核心規則 / Core rules

  • COOIS 依 SO + Material + Segment 加總全部 Open Quantity。/ COOIS Open Quantity is aggregated by SO + Material + Segment.
  • F 是母料 MB52 原始總量；G 採同單位優先且每母料只取一次：有同單位子料時擇一算 J/P；若完全無同單位子料，任意擇一算 J/P（不換算）並以紅字提示。/ F is the original mother MB52 total; G uses same-unit-first and pick-once: pick one same-unit child when available; otherwise pick any child without conversion and show G in red.
  • F+G 先覆蓋母料需求；不足才展開子料。/ F+G covers mother demand first; only the shortage expands to children.
  • Rule A 維持取消；Rule D 已恢復。直接需求永遠保留，先用母料餘量覆蓋，未覆蓋量才扣子料 MB52。/ Rule A remains removed; Rule D is restored. Direct demand remains visible, uses the mother balance first, and only the uncovered amount consumes child MB52.
  • 多母共用子料時，依 cutting、Schedule 列序、COOIS 母料列序逐列扣同一池。/ Shared-child stock is consumed by cutting, Schedule row order, and COOIS mother order.
  • 直接子料若同時可歸入多個母料，先列出全部衝突關係並請確認；確認後依母料 Open Qty 比例拆分直接需求再繼續，取消則整批停止。/ Direct child demand that could belong to multiple mothers lists every conflict for confirmation; confirm splits by mother Open Qty, cancel stops the run.
mother cover child = min(demand qty, H × conversion ratio)
Q provided qty = min(demand qty - mother cover child, stock available)
fulfilled = mother cover child + Q
R = stock available - Q

5. 合貼備料齊套 / Lamination Kit Ready

只有具有母料、至少一筆非 MH04 正需求，且所有非 MH04 正需求都足量時，整個母料群組標 Y。零需求、純直接需求與僅 MH04 群組保持空白。MH04 仍會輸出與配發，但不參與判定。
Y 判定使用內部原始數值（同一輪計算的 fulfilled 與 demand_total），避免格式化小數造成的邊界誤差。

A mother group is marked Y only when it has at least one positive non-MH04 demand and every positive non-MH04 demand is fully supplied. Zero-demand, direct-only, and MH04-only groups remain blank. MH04 rows are still exported and allocated but do not participate in the decision.
Y decision uses internal raw numbers from the same allocation pass (`fulfilled` vs `demand_total`) to avoid boundary errors from formatted decimals.

7. 常見問題 / Troubleshooting

  • 結果無法匯出：輸入或設定已變更，請重跑。/ Export disabled: inputs or settings changed; rerun.
  • G 欄紅字：此母料在有效 0028 中找不到任何同單位子料，系統改從任一子料擇一計算 J/P（不換算）。/ Red G column: this mother has no same-unit child in effective 0028, so the system picked any one child for raw J/P.
  • 直接需求歸屬不明：同一 SO + Segment 的子料連到多個母料；畫面列出 SO／母／子與開量，確認後按母料 Open Qty 比例拆分，取消則停止。/ Ambiguous direct demand: the child links to multiple mothers in the same SO + Segment; the UI lists SO / mother / child and Open Qty; confirm splits by mother Open Qty, cancel stops.
  • child stock 沒遞減：這是正確行為；它顯示原始總量，請看 stock available 與 remaining。/ child stock does not decrease: expected; it is the original total. Use stock available and remaining for the running balance.
  • 沒有 Y：零需求、純直接或 MH04-only 群組本來就不標 Y。/ No Y flag: zero-demand, direct-only, and MH04-only groups intentionally remain blank.
